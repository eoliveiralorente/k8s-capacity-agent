Legenda das Métricas

Cada barra mostra a porcentagem em relação à capacidade allocatable dos nodes do pool (recursos disponíveis para pods, após reservas do sistema).

CPU Usage consumo real

CPU efetivamente consumida pelos pods, medida pelo metrics-server (kubectl top). Reflete o uso atual do pool — quanto processamento está sendo utilizado neste momento.

CPU Requests reserva do scheduler

Soma dos resources.requests.cpu declarados nos pods. É a capacidade que o scheduler reserva para garantir placement. Alto request com baixo usage indica superprovisionamento.

Mem Usage consumo real

Memória (RAM) efetivamente consumida pelos pods, medida pelo metrics-server. Mostra pressão real de memória no pool — diferente do que foi reservado.

Mem Requests reserva do scheduler

Soma dos resources.requests.memory declarados nos pods. O scheduler usa esse valor para decidir se cabe um novo pod. Pool com requests altos pode rejeitar pods mesmo com usage baixo.

Usage vs Request: Usage é o que o pool consome agora; Request é o que foi reservado no agendamento. Compare os dois para identificar superprovisionamento (request alto, usage baixo) ou risco de pressão (usage ou request próximos de 100%).
Níveis das barras: < 70% — normal 70–84% — atenção ≥ 85% — pressão

Como pedir suporte

  1. Clique em Baixar pacote de suporte (admin). O arquivo não contém senhas, chaves, kubeconfigs nem logs das aplicações.
  2. Abra um chamado descrevendo o problema, o horário e anexe o pacote.
  3. Se o painel não abrir: kubectl -n capacity-agent exec deploy/capacity-agent -- python agent.py support-bundle -o - > suporte.zip
